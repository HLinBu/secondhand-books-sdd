# Data Model: 二手書交易平台 MVP

**Date**: 2026-11-10 | **Plan**: [plan.md](plan.md) | **Spec**: [spec.md](spec.md)

實體與欄位以規格書「核心資料」為準，每個欄位與規則都註明來源：

- 規格書核心資料、FR、NFR、Clarify：見 [spec.md](spec.md)
- P-xx：Plan 階段的資料缺口，人類接受
- AI-xx、V-xx：AI 推測與實作所需的值，人類於 Plan 階段接受
- 「設計決定」：agent 為了實作而做的結構選擇，不改變需求，交由人類在本階段審查

## 實體與欄位

### User（使用者）

| 欄位 | 來源 |
| --- | --- |
| 暱稱 | 規格書核心資料 |
| Email | 規格書核心資料；作為登入帳號，不可重複（設計決定） |
| 角色 | 規格書核心資料；一般使用者或管理員（AI-10） |
| 平均評價 | 規格書核心資料；合計當買家與當賣家收到的評價（Clarify） |
| 密碼 | P-01；雜湊保存 |
| Email 驗證狀態 | P-02 |
| 刪除帳號申請時間 | P-04；沒有申請時為空 |
| 停權狀態 | AI-06 |

**驗證規則**

- 密碼必須雜湊保存（NFR-003）。
- 未驗證 Email 的帳號不能上架或下單（FR-002、AI-01）。
- 被停權的帳號不能登入（FR-028、AI-06）。
- 管理員帳號由平台建立，不能自行註冊（AI-13）。
- 刪除帳號申請由管理員執行；有進行中訂單時不能執行（FR-005、AI-09）。
- 刪除帳號後，Order 的買家與賣家、Listing 的賣家、Review 的評價者與被評價者、Message 的寄件者與收件者、Dispute 的裁決者、後台操作紀錄的操作者設為空，畫面顯示「已刪除的使用者」；該使用者「上架中」的刊登改為「已下架」；收藏與站內通知一併刪除（Q-02）。
- 平均評價由該使用者收到的所有 Review 星等平均計算（FR-004）。

### Book（書目資料）

| 欄位 | 來源 |
| --- | --- |
| ISBN | 規格書核心資料；不可重複（設計決定，讓 ISBN 能帶入同一書目） |
| 書名 | 規格書核心資料 |
| 作者 | 規格書核心資料 |
| 出版社 | 規格書核心資料 |
| 版次 | 規格書核心資料 |
| 分類 | 規格書核心資料；教科書、文學小說、商業理財、語言學習、電腦資訊、藝術設計、兒童讀物、其他（V-01） |
| 封面 | 規格書核心資料；圖片，規則同刊登照片 |

**驗證規則**

- 書目與刊登分開存放，同一書目可以有多筆刊登（FR-007）。
- 輸入 ISBN 時從平台既有書目帶入；找不到時手動填寫並建立新書目（FR-006、AI-02）。

### Listing（刊登）

| 欄位 | 來源 |
| --- | --- |
| 賣家 | 規格書核心資料 |
| 書目 | 規格書核心資料 |
| 書況說明 | 規格書核心資料 |
| 價格 | 規格書核心資料；新台幣整數，至少 1 元（V-04） |
| 照片 | 規格書核心資料；1 到 5 張，另存成「刊登照片」（設計決定） |
| 狀態 | 規格書核心資料；上架中、交易中、已售出、已下架（AI-03） |
| 建立時間 | 設計決定；用於列表排序與到貨通知 |

**刊登照片**（設計決定：一筆刊登有多張照片）

| 欄位 | 來源 |
| --- | --- |
| 刊登 | Listing 的「照片」欄位 |
| 圖片檔 | FR-008 |

**驗證規則**

- 一筆刊登代表一本實體書（FR-009）。
- 照片 1 到 5 張，只接受 JPEG、PNG、WebP，單張最多 5 MB（FR-008、NFR-005、AI-11）。
- 「交易中」與「已售出」的刊登不能修改或下架（FR-010、AI-03）。
- 只有「上架中」的刊登可以被下單（FR-014）。
- 同一本書不可被賣出兩次（NFR-002）；鎖定方式見 research R-03。

**刊登狀態轉換**

| 從 | 事件 | 到 | 來源 |
| --- | --- | --- | --- |
| （無） | 賣家建立刊登 | 上架中 | FR-010 |
| 上架中 | 買家下單 | 交易中 | FR-015 |
| 交易中 | 訂單轉為「已取消」 | 上架中 | FR-015、Clarify |
| 交易中 | 訂單轉為「訂單完成」 | 已售出 | FR-015、AI-03 |
| 上架中 | 賣家下架，或管理員下架 | 已下架 | FR-010、AI-06 |

### Order（訂單）

| 欄位 | 來源 |
| --- | --- |
| 買家 | 規格書核心資料 |
| 賣家 | 規格書核心資料 |
| 刊登 | 規格書核心資料 |
| 成交價 | 規格書核心資料；下單當下的刊登價格 |
| 下單時間 | 規格書核心資料 |
| 訂單狀態 | 規格書核心資料；見下方「訂單狀態轉換」 |
| 買家收件資訊 | P-03；收件人姓名、手機、收件地址或取貨門市（V-05） |
| 訂單完成時間 | P-06 |
| 取消時間 | P-07 |
| 取消原因 | P-07；下單後 3 天未出貨、出貨前取消（買家）、出貨前取消（賣家）、爭議裁決買家有理 |

**驗證規則**

- 訂單狀態只能依轉換表變更（FR-021、NFR-001）。
- 賣家不能對自己的刊登下單（FR-014、AI-08）。
- 下單後 3 天未出貨自動取消，從下單時間起算（FR-019）。
- 出貨前買家或賣家可取消；出貨後不能取消（FR-027）。
- 買家收件資訊只在待出貨、運送中、待確認收貨、爭議處理中提供給賣家（FR-022、NFR-007）。
- 評價期限從訂單完成時間起算 14 天（FR-026）。

### Shipment（物流紀錄）

| 欄位 | 來源 |
| --- | --- |
| 訂單 | 規格書核心資料；一筆訂單一筆物流紀錄（設計決定） |
| 物流方式 | 規格書核心資料；超商取貨、宅配，皆為模擬（V-02） |
| 託運單號 | 規格書核心資料 |
| 物流狀態 | 規格書核心資料；已出貨、已取貨（V-03） |
| 出貨時間 | 規格書核心資料 |
| 取貨時間 | 規格書核心資料 |

**驗證規則**

- 物流以模擬方式呈現，不串接真實物流（FR-017）。
- 賣家標記出貨時建立物流紀錄，物流狀態為「已出貨」（FR-016、V-03）。
- 買家標記「已取貨」時，物流狀態改為「已取貨」並記錄取貨時間（FR-017、V-03）。
- 取貨後 3 天內未確認也未提出爭議，自動確認收貨，從取貨時間起算；爭議處理中不自動確認（FR-020、AI-05）。

### Dispute（爭議案件）

| 欄位 | 來源 |
| --- | --- |
| 訂單 | 規格書核心資料；一筆訂單最多一筆爭議 |
| 原因 | 規格書核心資料 |
| 證據 | 規格書核心資料；照片，規則同刊登照片（Clarify：爭議證據為照片） |
| 裁決結果 | 規格書核心資料；賣家有理或買家有理，裁決前為空 |
| 裁決者 | 設計決定；記錄是哪位管理員裁決 |
| 裁決時間 | 設計決定 |

**驗證規則**

- 只能對「待確認收貨」的訂單提出（FR-023、FR-024）。
- 由管理員依刊登的實拍照片、爭議證據與該刊登的站內訊息裁決（FR-025）。

### Review（交易評價）

| 欄位 | 來源 |
| --- | --- |
| 訂單 | 規格書核心資料 |
| 評價者 | 規格書核心資料 |
| 被評價者 | 規格書核心資料 |
| 星等 | 規格書核心資料；1 到 5 的整數（AI-04） |
| 內容 | 規格書核心資料 |
| 建立時間 | 設計決定 |

**驗證規則**

- 只有「訂單完成」的訂單可以評價，期限為完成後 14 天（FR-026）。
- 評價者必須是該訂單的買家或賣家，被評價者是另一方（FR-026）。
- 同一評價者對同一訂單只能評價一次（AI-04）。

### Message（站內訊息，建議模組）

| 欄位 | 來源 |
| --- | --- |
| 刊登 | 規格書核心資料 |
| 寄件者 | 規格書核心資料 |
| 收件者 | 規格書核心資料 |
| 內容 | 規格書核心資料 |
| 時間 | 規格書核心資料 |

**驗證規則**

- 訊息必須針對某筆刊登（FR-031）。

### Favorite（收藏與上架通知，建議模組）

| 欄位 | 來源 |
| --- | --- |
| 使用者 | 規格書核心資料 |
| 書目 | 規格書核心資料 |
| 是否通知 | 規格書核心資料 |

**驗證規則**

- 收藏對象是書目，不是刊登（規格書核心資料）。
- 同一使用者對同一書目只能收藏一次（設計決定）。
- 開啟通知時，該書目有新刊登上架就建立站內通知（FR-033、AI-07）。

### 站內通知（P-08、AI-07）

規格書核心資料沒有這個實體。P-08「到貨通知的發送紀錄」與 AI-07「以站內通知發送」合併成這個實體（設計決定）。

| 欄位 | 來源 |
| --- | --- |
| 收件使用者 | FR-033 |
| 相關刊登 | FR-033 |
| 內容 | FR-033 |
| 建立時間 | P-08 |
| 是否已讀 | 設計決定 |

### 後台操作紀錄（P-05）

規格書核心資料沒有這個實體，依品質要求「管理後台須有角色權限與操作紀錄」補上。

| 欄位 | 來源 |
| --- | --- |
| 操作者 | FR-030 |
| 時間 | FR-030 |
| 對象 | FR-030 |
| 內容 | FR-030 |

**驗證規則**

- 後台每一筆管理操作都必須留下紀錄（FR-030、SC-006）。
- 紀錄只能新增，不能修改或刪除（設計決定，避免紀錄被竄改）。

## 實體關聯

| 關聯 | 數量 | 來源 |
| --- | --- | --- |
| Book → Listing | 一個書目對多筆刊登 | 規格書核心資料說明 |
| User（賣家）→ Listing | 一位賣家對多筆刊登 | Listing 的「賣家」欄位 |
| Listing → 刊登照片 | 一筆刊登對 1 到 5 張照片 | FR-008、AI-11 |
| Listing → Order | 一筆刊登同時最多一筆未取消的訂單；取消後可再有新訂單 | FR-015、NFR-002、Clarify |
| User（買家、賣家）→ Order | 每筆訂單有一位買家、一位賣家 | Order 的「買家」「賣家」欄位 |
| Order → Shipment | 一對一 | 設計決定 |
| Order → Dispute | 一筆訂單最多一筆爭議 | 流程圖：爭議只能從「待確認收貨」進入，裁決後訂單即結束 |
| Order → Review | 一筆訂單最多兩則評價（買家一則、賣家一則） | FR-026、AI-04 |
| Listing → Message | 一筆刊登對多則訊息 | Message 的「刊登」欄位 |
| User、Book → Favorite | 使用者收藏書目，同一組合只有一筆 | Favorite 的「使用者」「書目」欄位 |
| User → 站內通知 | 一位使用者對多則通知 | 站內通知的「收件使用者」欄位 |
| User（管理員）→ 後台操作紀錄 | 每筆紀錄有一位操作者 | 後台操作紀錄的「操作者」欄位 |

## 訂單狀態轉換

依 spec「訂單狀態流程」，共 6 個狀態。終止狀態為「訂單完成」與「已取消」。所有轉換都經過同一個轉換函式（research R-04）。

| 從 | 事件 | 執行者 | 到 | 刊登連動 |
| --- | --- | --- | --- | --- |
| （無） | 買家下單 | 買家 | 待出貨 | 上架中 → 交易中 |
| 待出貨 | 賣家出貨 | 賣家 | 運送中 | — |
| 待出貨 | 下單後 3 天未出貨 | 系統 | 已取消 | 交易中 → 上架中 |
| 待出貨 | 出貨前取消 | 買家或賣家 | 已取消 | 交易中 → 上架中 |
| 運送中 | 買家標記已取貨 | 買家 | 待確認收貨 | — |
| 待確認收貨 | 買家確認收貨 | 買家 | 訂單完成 | 交易中 → 已售出 |
| 待確認收貨 | 取貨後逾 3 天 | 系統 | 訂單完成 | 交易中 → 已售出 |
| 待確認收貨 | 買家提出爭議 | 買家 | 爭議處理中 | — |
| 爭議處理中 | 裁決賣家有理 | 管理員 | 訂單完成 | 交易中 → 已售出 |
| 爭議處理中 | 裁決買家有理 | 管理員 | 已取消 | 交易中 → 上架中 |

## 資料缺口與判定結果（AI 推測）

以下資料在規格書其他段落有要求，但「核心資料」表沒有對應欄位或實體。人類於 2026-11-10 判定全部接受，已補進上方的實體。

| 編號 | 缺少的資料 | 規格書或 spec 出處 | 判定 | 補在哪裡 |
| --- | --- | --- | --- | --- |
| P-01 | User 的密碼 | 品質要求「密碼須雜湊保存」；FR-001 | 接受 | User |
| P-02 | User 的 Email 驗證狀態 | 帳號模組「需驗證 Email」；FR-002 | 接受 | User |
| P-03 | 買家收件資訊 | 品質要求「買家收件資訊僅在訂單進行中提供給賣家」；FR-022 | 接受 | Order |
| P-04 | 刪除帳號申請 | 品質要求「使用者可申請刪除帳號」；FR-005（Clarify：由管理員執行） | 接受 | User（刪除帳號申請時間） |
| P-05 | 後台操作紀錄 | 品質要求「管理後台須有角色權限與操作紀錄」；FR-030 | 接受 | 新增「後台操作紀錄」實體 |
| P-06 | 訂單完成時間 | 業務規則「訂單結束後 14 天內可互評」需要起算時間；FR-026 | 接受 | Order |
| P-07 | 訂單取消時間或原因 | 刊登解除鎖定與 3 種取消情況（FR-015、FR-019、FR-027、FR-025）；核心資料沒有記錄取消的欄位 | 接受 | Order（取消時間、取消原因） |
| P-08 | 到貨通知的發送紀錄 | 留存模組「指定書籍上架時通知」；FR-033 | 接受 | 新增「站內通知」實體（原放在 Favorite，AI-07 接受後改為獨立實體） |
