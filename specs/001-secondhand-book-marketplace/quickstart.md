# Quickstart: 本機執行與驗收

**Date**: 2026-11-10 | **Plan**: [plan.md](plan.md)

實作完成後，用這份文件在本機啟動網站並驗收。下列指令在 Implement 階段完成後才能執行。

## 前置條件

- Windows、macOS 或 Linux，已安裝 [uv](https://docs.astral.sh/uv/)
- Python 3.12（可由 uv 自動安裝）

## 啟動

```bash
uv sync
```

```bash
cp .env.example .env
```

```bash
uv run python manage.py migrate
```

```bash
uv run python manage.py createsuperuser
```

```bash
uv run python manage.py runserver
```

開啟 `http://127.0.0.1:8000/`。後台在 `http://127.0.0.1:8000/admin/`。

Email 驗證信不會真的寄出，會存成檔案放在 `.env` 指定的資料夾，打開信件裡的連結即可完成驗證（research R-01）。

## 執行測試

```bash
uv run python manage.py test
```

預期結果：全部測試通過。每個系統操作（[contracts/system-operations.md](contracts/system-operations.md)）至少有一個成功與一個前置條件不符的測試。

## 期限處理

```bash
uv run python manage.py process_order_deadlines
```

處理 3 天未出貨與 3 天未確認的訂單（OP-17）。展示時可手動執行；測試時以指定的「現在時間」驗證，不必真的等 3 天。

## 驗收情境

用假資料逐一操作。帳號 Email 一律使用 `@example.com`：

| 帳號 | 用途 |
| --- | --- |
| 測試買家A | 一般使用者 |
| 測試賣家B | 一般使用者 |
| 測試買家C | 一般使用者 |
| 測試管理員 | 用 `createsuperuser` 建立 |

### 情境 1：完整交易流程（SC-001）

| 步驟 | 操作 | 預期結果 | 依據 |
| --- | --- | --- | --- |
| 1 | B 註冊、開啟驗證信連結、登入 | B 可以登入 | OP-01 至 OP-03 |
| 2 | B 建立刊登，附 1 張 JPEG 照片 | 刊登出現在首頁搜尋結果，狀態上架中 | OP-07、OP-10 |
| 3 | A 下單並填寫收件資訊 | 訂單「待出貨」，刊登「交易中」 | OP-13 |
| 4 | B 標記出貨，選超商取貨 | 訂單「運送中」 | OP-14 |
| 5 | A 標記已取貨 | 訂單「待確認收貨」 | OP-15 |
| 6 | A 確認收貨 | 訂單「訂單完成」，刊登「已售出」 | OP-16 |
| 7 | A、B 互評 | 雙方平均評價更新；再評一次被拒絕 | OP-21 |

### 情境 2：不可重複售出（SC-003）

| 步驟 | 操作 | 預期結果 | 依據 |
| --- | --- | --- | --- |
| 1 | 執行同時下單的自動測試 | 只有一筆訂單成立 | OP-13、research R-03 |
| 2 | B 對自己的刊登下單 | 被拒絕 | OP-13、AI-08 |

### 情境 3：期限自動轉換（SC-004）

| 步驟 | 操作 | 預期結果 | 依據 |
| --- | --- | --- | --- |
| 1 | 執行期限處理的自動測試：下單滿 3 天未出貨 | 訂單「已取消」，刊登回到「上架中」 | OP-17 |
| 2 | 執行期限處理的自動測試：取貨滿 3 天未確認 | 訂單「訂單完成」 | OP-17 |
| 3 | 執行期限處理的自動測試：爭議處理中滿 3 天 | 訂單維持「爭議處理中」 | OP-17、AI-05 |

### 情境 4：取消與爭議（SC-002）

| 步驟 | 操作 | 預期結果 | 依據 |
| --- | --- | --- | --- |
| 1 | 訂單「待出貨」時 B 取消 | 訂單「已取消」，刊登回到「上架中」 | OP-19 |
| 2 | 訂單「運送中」時 A 嘗試取消 | 被拒絕 | OP-19 |
| 3 | 訂單「待確認收貨」時 A 提出爭議並附照片 | 訂單「爭議處理中」 | OP-20 |
| 4 | 管理員在後台開啟爭議案件 | 看得到刊登照片、爭議證據、站內訊息 | OP-24 |
| 5 | 管理員裁決買家有理 | 訂單「已取消」，刊登回到「上架中」，後台有操作紀錄 | OP-24 |
| 6 | 對已取消的訂單評價 | 被拒絕 | OP-21 |

### 情境 5：個資、權限與後台（SC-006、SC-007）

| 步驟 | 操作 | 預期結果 | 依據 |
| --- | --- | --- | --- |
| 1 | 訂單「運送中」時 B 開啟訂單詳情 | 看得到 A 的收件資訊 | OP-18 |
| 2 | 訂單完成後 B 開啟訂單詳情 | 看不到 A 的收件資訊 | OP-18 |
| 3 | A 開啟 `/admin/` | 被拒絕 | OP-22 |
| 4 | 未驗證 Email 的 C 嘗試建立刊登 | 被拒絕 | OP-07、AI-01 |
| 5 | 上傳 6 MB 的圖片、或改了副檔名的文字檔 | 被拒絕並說明原因 | OP-07、AI-11 |
| 6 | 管理員停權 C | C 無法登入，後台有操作紀錄 | OP-26 |
| 7 | A 有進行中訂單時申請刪除帳號，管理員執行 | 被拒絕；訂單結束後再執行則成功 | OP-27、AI-09 |

### 情境 6：搜尋、訊息與通知（SC-005）

| 步驟 | 操作 | 預期結果 | 依據 |
| --- | --- | --- | --- |
| 1 | 依書名、作者、ISBN 各搜尋一次 | 只出現符合條件的刊登 | OP-10 |
| 2 | 依分類、價格篩選 | 只保留符合條件的刊登 | OP-11 |
| 3 | A 對 B 的刊登傳訊息 | B 看得到訊息與所屬刊登 | OP-28 |
| 4 | C 收藏某書目並開啟通知，B 上架同書目 | C 的站內通知出現一則 | OP-29 至 OP-31 |
